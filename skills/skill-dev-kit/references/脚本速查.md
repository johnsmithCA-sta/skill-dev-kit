# 脚本速查（skill-dev-kit 5 个自动化脚本）

> 全部零第三方依赖（仅 Python 标准库 + 可选 gh / skillhub CLI），可直接接入 CI 门禁。
> 用法速见表见 SKILL.md §四；本文件为完整命令、退出码、示例与踩坑。

## 0. 一键执行顺序（发布时）

```bash
# 1) 发布前预检（自动覆盖清单 1/3/5/6/16，含归属检查）
python3 scripts/preflight_release.py <技能目录> --platform skillhub

# 2) SkillHub 目录直发（默认路径）：先 dry-run 预检，确认目录内无 LICENSE 后实发
skillhub publish <技能目录> --dry-run --json
skillhub publish <技能目录> --changelog "..."

# 3) GitHub tag 保护（可选，仅 GitHub 发布）
python3 scripts/setup_gh_ruleset.py --dry-run && python3 scripts/setup_gh_ruleset.py
```

---

## 1. preflight_release.py — 发布预检

发布前一键检查 5 项：敏感信息扫描 / frontmatter 字段校验 / 必含文件 / git 未跟踪文件告警 / 归属检查。

```bash
# SkillHub 平台预检（默认）
python3 scripts/preflight_release.py <技能目录> --platform skillhub
# GitHub 平台预检（严格模式：低危告警也判失败）
python3 scripts/preflight_release.py <技能目录> --platform github --strict
# 静默输出（只打印结果行，便于 CI）
python3 scripts/preflight_release.py <技能目录> --quiet
# 豁免归属检查（仅自用/第三方技能确不需要时，需在发布记录中声明理由）
python3 scripts/preflight_release.py <技能目录> --skip-ownership
```

- **退出码**：`0` = PASS（仅告警可放行）/ `1` = FAIL（存在高危：API key、明文 token、缺 frontmatter 字段、缺 author/Copyright 等）。
- **敏感分级**：`critical`（skh_/ghp_/sk-/AKID/COS secret/token 赋值/明文密码）→ 必然 FAIL；`warning`（/Users 路径/邮箱/疑似密码/手机号）→ 默认仅告警，`--strict` 时 FAIL。
- **归属检查（critical，恒开，可豁免）**：frontmatter `author` 非空 + 源码目录 LICENSE 含 `Copyright (c)` 行（正则，兼容全角/©写法；LICENSE.md/.txt 自动识别）。homepage 仓库真实性由人工/`gh api` 核验。
- **平台规范**：skillhub 需 frontmatter 含 name/slug/displayName/summary/description/version/license + SKILL.md/scripts；github 需 name/description/version/license + README/LICENSE/SKILL.md（支持 skills/<name>/SKILL.md 放宽）。

## 2. make_skillhub_zip.py — 打包归档（非发布必经）

> **定位变更（v1.5.0）**：SkillHub CLI（v2026.8.5+）支持目录直发 `skillhub publish <目录>`，本脚本从「发布必经步骤」降级为**离线归档 / 定制打包**工具。仍用于：留档 zip、`--keep-license` 出 GitHub 包、无 skillhub CLI 环境下预生成上传包。

读 SKILL.md `version` 自动命名 `<顶层名>-v<version>.zip`，排除 `.git/__pycache__`，**默认排除 LICENSE**，校验 ≤10MB。

```bash
# 默认打包（自动版本命名，排除 LICENSE）
python3 scripts/make_skillhub_zip.py <技能目录>
# 指定输出路径
python3 scripts/make_skillhub_zip.py <技能目录> --out skill.zip
# 文件名不带版本号
python3 scripts/make_skillhub_zip.py <技能目录> --no-version
# 保留 LICENSE（仅 GitHub 用）
python3 scripts/make_skillhub_zip.py <技能目录> --keep-license
```

- **退出码**：`0` = 成功 / `1` = 失败（超 10MB / 无 version / 目录不存在）。
- **踩坑**：SkillHub 接口对包内 LICENSE 返回 400「不允许的文件类型: LICENSE」，故默认排除；License 由 frontmatter `license: MIT` 字段声明即可。**注意：目录直发路径不排除 LICENSE**——直发前须人工把 LICENSE 移出发布目录（或用本脚本打包后发 zip）。

## 3. setup_gh_ruleset.py — GitHub tag 保护

用完整 JSON body 经 `gh api` 创建 ruleset（规避 `-f/--input` 混用 422 坑），默认 tag 保护：禁止删除 + 禁止强制覆盖。

```bash
# 当前 git 仓库目录下运行（自动解析 owner/repo）；先打印将发送的 JSON
python3 scripts/setup_gh_ruleset.py --dry-run
# 实际创建（默认对所有 tag 生效）
python3 scripts/setup_gh_ruleset.py
# 列出现有 rulesets
python3 scripts/setup_gh_ruleset.py --list
# 显式指定仓库 / 名称 / 生效模式
python3 scripts/setup_gh_ruleset.py --repo owner/repo --name "Tag Protection" --enforcement active
```

- **退出码**：`0` = 成功 / `1` = 失败（同名已存在需手动处理 / gh 未认证）。
- **依赖**：`gh` CLI 已认证（`gh auth status`），仓库 admin 权限。
- **踩坑**：传 `pattern="v*"` 触发 422（需完整 ref 语法 `refs/tags/*`）；省略 conditions 即对所有 tag 生效，最稳妥。

## 4. eval_trigger.py — 触发词评估

对标 Anthropic skill-creator 的「description 触发词优化」：生成 should-trigger / should-not-trigger 评估集，并静态检查 SKILL.md 触发词覆盖率。

```bash
# 生成评估集模板（should + should-not 各 N 条，人工/LLM 审阅扩充）
python3 scripts/eval_trigger.py <技能目录> --gen --count 20
# 静态检查触发词覆盖率（默认动作）
python3 scripts/eval_trigger.py <技能目录> --check
# 自定义阈值（默认 0.7）
python3 scripts/eval_trigger.py <技能目录> --check --threshold 0.8
# 指定评估集输出路径
python3 scripts/eval_trigger.py <技能目录> --gen --out evals.json
# 校验 description 本体质量（第三人称/动作动词/场景/无 how/排他边界，5/5 才 PASS）
python3 scripts/eval_trigger.py <技能目录> --desc-check
# 直接校验给定描述文本（快速试错，无需技能目录）
python3 scripts/eval_trigger.py . --desc-check --desc "Helps with documents"
```

- **退出码**：`0` = PASS（覆盖达标 / desc-check 5/5）/ `1` = FAIL（存在未覆盖意图 / desc-check 有不合格项）/ `2` = REVIEW（覆盖率达标但仍有遗漏，人工确认）。
- **原理**：解析 SKILL.md「## 触发词」章节，与预期意图清单做归一化子串比对。
- **desc-check**：静态校验 frontmatter description 的 5 项质量规则（第三人称/动作动词/场景或文件类型/无 how/排他边界），规则来源见 `references/SKILL.md 编写规范.md` §七，配套执行纪律见 `references/反模式清单.md`。

## 5. eval_loop.py — 评测循环

对标 Anthropic skill-creator 的 run_eval + aggregate_benchmark：with-skill vs baseline 对比 + 断言评分聚合为 benchmark.json。

```bash
# 执行各用例 run_cmd.txt 并聚合（目录约定见下）
python3 scripts/eval_loop.py <evals目录> --run --aggregate
# 仅聚合已有 grading.json → benchmark.json
python3 scripts/eval_loop.py <evals目录> --aggregate
# 指定聚合输出路径
python3 scripts/eval_loop.py <evals目录> --aggregate --out bench.json
```

**目录约定**（每个测试用例一个子目录）：

```
evals_dir/
├── case-01/
│   ├── eval.json        # {"prompt":..., "assertions":[...]} 断言=期望输出应包含的要点
│   ├── run_cmd.txt      # 可选：执行命令，产物写入 output/
│   ├── output/          # 运行产物（带技能）
│   ├── baseline/        # 基线产物（不带技能）※预留：当前聚合未参与
│   └── grading.json     # 评分结果：{"assertions":[{"text":..,"pass":true,"evidence":..}]}
└── case-02/ ...
```

- **退出码**：`0` = 聚合成功（PASS/REVIEW）/ `1` = 失败（无目录/无用例）。
- **评分降级策略**：grading.json 存在 → 直接读取；否则按 eval.json.assertions 做子串包含启发式评分；无断言 → skip。
- **判定**：均分 ≥0.7 → PASS；0–0.7 → REVIEW；无数据 → NO-DATA。
- **注意**：`baseline/` 目录为预留（文档承诺先于实现），当前聚合只读 `output/` 与 `grading.json`。

## 6. 接入 CI（可选）

```bash
# 发布门禁示例（GitHub Actions / 本地 pre-commit）
python3 scripts/preflight_release.py . --platform skillhub --strict --quiet \
  && python3 scripts/eval_trigger.py . --check \
  && skillhub publish . --dry-run --json
```
