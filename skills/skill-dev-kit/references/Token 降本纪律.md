# Token 降本纪律

> 来源：个人实战 ~1.2M tokens 消耗归因 + 技能开发实录，2026-08-24 资产化。
> 定位：技能开发/执行时控制 token 消耗的**四条强制纪律 + 量化驱动方法**。四条纪律叠加可压缩 50–60%。
> 铁律：**先小样本验证，再全量执行；能落盘不回流，能结论不 dump。**

## 1. 消耗归因基准（先知道钱花哪了）

个人实战 ~1.2M tokens 的真实分布——开发/调试一个技能时，消耗大头依次是：

| 消耗项 | 占比 | 根因 | 对策 |
|---|---|---|---|
| 调试循环 | 28% | 改一行跑一遍、反复试错 | 小样本先行验证（纪律 1） |
| 大文件反复读取 | 24% | 整文件 cat / 重复读同一大文件 | 输出压缩：head/tail/精准提取（纪律 2） |
| 代码写入 | 19% | 整段重写、反复覆盖 | 增量 Edit、避免整文件重写 |
| 上下文累积 | 17% | 中间产物长期挂在上下文不落盘 | 分阶段落盘、子代理隔离（纪律 3） |
| OCR 输出 + 图片 | 12% | 长 OCR 文本/截图反复进上下文 | 长文本 + 截图验证收敛（纪律 4） |

> 结论：**调试与重复读取占一半以上**——降本优先改「读」与「试」的方式，而不是压缩正文内容。

## 2. 四条强制纪律（可压缩 50–60%）

### 纪律 1：小样本先行验证（省 ~14%）

解析/处理新格式前，先打印 1 页/1 条样本确认结构，再全量执行。

```bash
# 先看 1 页，确认结构后再全量
python3 -c "print(open('data.pdf','rb').read()[:400])"
head -5 大文件.csv
# 全量前先 dry-run 1 条：python3 main.py --sample 1
```

### 纪律 2：输出压缩（省 ~15%）

调试命令统一 `head/tail`、`python -c` 精准提取，**禁整文件 cat**；大文件只读需要的行段。

```bash
# 反模式（24% 大头的来源）：cat 整个 5 万行文件 / 反复读取同一 PDF
# 正确做法：
grep -n "ERROR" big.log | head -20
python3 -c "import json;d=json.load(open('data.json'));print([k for k in d][:10])"
tail -50 big.log
```

### 纪律 3：子代理隔离（省 ~22%）

大文件读取/格式探测/耗时子任务交给子代理，**主线程只收结论**，中间产物不回流上下文。

```text
主代理 ──派发──> 子代理：读 200MB 文件、探测格式、汇总为 5 行结论
主代理 <──收结论── 子代理（中间文本不回流，避免上下文膨胀）
适用：大文件解析、批量抓取、格式探测、独立校验
```

### 纪律 4：验证收敛（省 ~5%）

中间迭代用 DOM/JS/文本断言验证，**截图仅最终一次**；长任务分阶段落盘，不把中间产物留在上下文。

```bash
# 中间迭代：文本断言 / DOM 检查，不截图
python3 -c "assert '期望内容' in open('out.html').read(), '渲染失败'"
# 仅最终结果截图/长文本输出一次；阶段产物写文件，下阶段从文件读
```

## 3. 量化驱动优化（每轮改进都要算账）

**要点**：每轮改进用 token 估算验证收益，识别高消耗环节，优化有的放矢——**没有量化的降本都是玄学**。

某批量化查询技能实测（具体案例档案留个人工作区，此处仅保留可复用的归因数据）：

| 轮次 | 单家消耗 | 优化动作 | 降幅 |
|---|---|---|---|
| 初始 | 61.5k | — | — |
| 第 1 轮 | 35.4k | 识别「检索 45%」高消耗 → 合并重复检索 | -42% |
| 第 2 轮 | 12.5k | 识别「迭代 20k」→ 分阶段落盘 + 子代理隔离 | -65% |
| 累计 | — | 量化驱动，逐步收敛 | **-80%** |

度量方法（零依赖）：
```python
# 用脚本对每次执行的上下文长度/输出字节做粗略估算，记录趋势
def rough_tokens(text: str) -> int:
    """粗略估算：中文≈1 token/字，英文≈1 token/4 字符。"""
    import re
    cn = len(re.findall(r"[\u4e00-\u9fff]", text))
    en = len(re.findall(r"[A-Za-z0-9]", text))
    return cn + en // 4

# 每轮记录：输入侧(读取字节) + 输出侧(打印字节)，对比优化前后
```

## 4. 降本自查迷你清单（每次任务收尾前过一遍）

- [ ] **小样本**：新格式/新数据首次处理前，先打印 1 条样本确认结构了吗？
- [ ] **压缩**：全程没有 `cat` 整个大文件、没有整段重复输出？
- [ ] **隔离**：大文件读取/格式探测交给子代理或落盘，中间产物没回流上下文？
- [ ] **收敛**：截图/长文本只在最终阶段输出一次？
- [ ] **落盘**：长任务中间产物已写文件，下一阶段从文件续读而非上下文？
- [ ] **增量写**：代码修改用增量 Edit，未整文件反复重写？
- [ ] **量化**：本轮消耗较上轮有记录、有对比、有结论（而不是「感觉变快了」）？

> 每 3–4 个「否」就值得停下来重排执行方式——四条纪律的收益大头在**执行的第一次就做对**。
