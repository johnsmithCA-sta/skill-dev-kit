# 反模式清单

> 来源：社区共识反模式 15 条 + 1 条生态新增，另补 4 条个人实战，共 20 条。
> 定位：写 SKILL.md / 写脚本前**先扫一遍**，命中即改。每条 = 反模式 → 正确做法。
> 用法：新技能开发完成、发布前，对照本表逐条自检；发现自己踩过表中没列的坑，按同样格式补行。

## 高频条目展开（命中率最高的 8 条）

### #2 description 模糊 —— 命门级
```text
反模式: "文档处理" / "Helps with documents"
正确:   "提取 PDF 表格转 CSV" / "创建带修订标记的 Word 文档用于法律审查"
检验:   eval_trigger.py <技能目录> --desc-check（5 项静态校验，任一项不过即 FAIL）
```

### #4 所有内容塞进一个文件
```text
反模式: SKILL.md 一个文件 15KB，正文同时承担方法论+命令速查+清单+示例
正确:   L2 正文 <5000 token；清单/方法学/速查拆到 references/，按需加载
检验:   wc -c SKILL.md；正文 token ≈ 字节数/4 中文（<5000 达标）
```

### #7 确定性逻辑让模型「想」出来
```text
反模式: 让 LLM 心算/脑补校验码、日期计算、数据聚合
正确:   确定性计算/校验/排版写成脚本让 AI 运行；创作部分才交模型
```

### #9 不处理错误、返回裸字符串
```text
反模式: 接口失败返回 "" 或抛出笼统异常码，下游无从判断
正确:   {ok:false, error:{code, message, retryable}}；错误消息含问题定位+正确示例
详见:   references/错误处理与可靠性纪律.md（纪律 4/7）
```

### #17 硬编码文件名列表（个人实战①）
```text
反模式: FILENAMES = ["2024-Q1.xlsx", "2024-Q2.xlsx", ...]——新增文件要改代码
正确:   目录自动扫描 + 正则提取：
    import re, glob
    files = sorted(glob.glob("data/*.xlsx"), key=lambda p: re.search(r"(\d{4})[-_]?Q[1-4]", p).group(0))
    # 脱敏 + 复用前提：新文件加入目录即自动纳入，无需改脚本
```

### #18 正则缺边界致误报（个人实战②）
```text
反模式: 手机号匹配 \d{11}——命中身份证里的 11 位连续数字；年份 2026 被当价格/金额
正确:   加数字边界 + 校验器：
    import re
    PHONE = re.compile(r"(?<![0-9])1[3-9]\d{9}(?![0-9])")   # 前后非数字
    def is_valid_phone(s):
        return bool(PHONE.match(s)) and s[1] in "3456789"   # 再加号段/校验器兜底
    # 同法：身份证 MOD11-2 校验码、银行卡 Luhn、统一社会信用代码 GB32100 校验器
```

### #19 硬编码铁律不容偏离（个人实战③）
```text
反模式: SKILL.md 全是 MUST/NEVER 且无出口——用户意图与规范冲突时模型要么硬撞要么静默偏离，
        固化反过来限制了 agent 的判断力
正确:   ① Constraints 节必带「逃逸条款」：冲突时优先保障用户数据与意图 + 显式说明偏离理由
            与替代动作（偏离留痕，必要时降级人工）；
        ② 固化是「可更新指南」：版本治理里标注失效触发条件（见 知识分层与版本治理.md §三）
```

### #20 探索型/发散型任务写死流程（个人实战④）
```text
反模式: 给"帮我分析这份数据有什么规律"类开放任务写成 1234 固定步骤——把探索压成流水线，丢失发散空间
正确:   先判任务类型：确定性/流程型（发布、转换、校验）→ 写死 Steps + 完整命令；
        探索型/发散型（分析、创作、诊断）→ 只给目标、约束、质量门槛与工具清单，步骤留给模型
```
