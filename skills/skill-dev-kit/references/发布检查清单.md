# 技能发布前必过检查清单（15 项）

> 复制本清单逐项勾选，全部通过后方可发布。配套脚本 `scripts/preflight_release.py` 可自动覆盖第 1/3/5/6 项。

```
[ ] 1. 敏感扫描：个人路径/账号/密码/token/领域数据，全部参数化或泛化
        （privacy-audit L1 退出码 0 通过）
[ ] 2. 版本号：SKILL.md version 与发布 tag 一致（语义化 X.Y.Z）
[ ] 3. SkillHub：ZIP ≤10MB；frontmatter 含 slug/displayName/summary/license
[ ] 4. GitHub：技能位于 skills/<name>/SKILL.md；含 README/LICENSE/CONTRIBUTING
[ ] 5. 预检：preflight_release.py --dry-run 通过
        python3 scripts/preflight_release.py <技能目录> --platform skillhub
[ ] 6. git status 确认无未跟踪文件遗漏
[ ] 7. 推送后验证远程文件完整性（gh api / skillhub verify）
[ ] 8. 含临时凭证的中间文件已删除
[ ] 9. changelog 最终确认（SkillHub 同版本不可重发、发布后无法修改）
[ ] 10. 发布后记录 URL、版本、审核状态
[ ] 11. 发布目录/zip 内不含 LICENSE 文件
        —— SkillHub 拒收（HTTP 400"不允许的文件类型: LICENSE"）
        —— 目录保留 LICENSE 供 GitHub，另建无 LICENSE 发布目录
[ ] 12. 正式发布前人工核对发布目录文件清单
        —— dry-run 只校验 metadata+打包，不检查平台文件类型白名单
[ ] 13. 用计划上线的所有模型 +「真人说话」式复杂 prompt 测试过
        —— 干净测试提示会骗人，上线后意外崩（带错字/缩写/乱文件名）
[ ] 14. 边缘情况（缺失输入、错误文件、无权限）有处理
[ ] 15. 脚本自包含/依赖声明清晰、错误可读
```

## 一键执行顺序

```bash
# 1) 发布前预检（自动覆盖 1/3/5/6）
python3 scripts/preflight_release.py <技能目录> --platform skillhub

# 2) 打包（默认排除 LICENSE，自动版本命名）
python3 scripts/make_skillhub_zip.py <技能目录>

# 3) GitHub tag 保护（可选，仅 GitHub 发布）
python3 scripts/setup_gh_ruleset.py --dry-run && python3 scripts/setup_gh_ruleset.py

# 4) 发布
skillhub publish <技能目录>/<顶层名>-v<version>.zip --changelog "..."
```
