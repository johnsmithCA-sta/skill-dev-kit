# 技能发布前必过检查清单（16 项）

> 复制本清单逐项勾选，全部通过后方可发布。配套脚本 `scripts/preflight_release.py` 可自动覆盖第 1/3/5/6/16 项，另做 name 规范、正文体积、§ 章节引用、版本与 tag、评测宣称一致性五项检查，以及**结构规范检查**（引用完整性 / description 触发面 / 保留词 / 引号卫生 / 打包卫生为告警；包内含 README / 孤儿引用 / references 元数据 / 索引漂移 / 路由表缺 doNotUse 列只登记不判定）；`scripts/check_deps.py` 单独负责依赖声明完整性。
>
> ⚠️ **先判改动类型再勾选**——16 项全量串行会把「改一句 description」和「发首版」按同一成本处理。见下方「改动分级」。

## 改动分级：先定改动类型，再选最小但足够的检查集

**自动项 5 项（1/3/5/6/16）永远全跑，不纳入分级**——它们零成本，裁它们省不了任何东西；而且红线项恰好都落在自动项上，「不能省」和「本来就零成本」是同一件事。分级只裁**人工项 11 项**。

| 层 | 项 | 说明 |
|---|---|---|
| **L0 人工红线**（无条件必过） | 2 版本号一致 · 11 不含 LICENSE · 16 的第三方受限内容反向检查 | 出错即不可逆或违规，与改动类型无关。16 的自动部分（author / Copyright）在 preflight，反向检查必须人工，**任何改动类型都查** |
| **L1 改动相关**（按类型裁剪） | 4 · 8 · 12 · 13 · 14 · 15 | 见下映射表；横跨多类型取并集 |
| **L2 发布流程收尾**（不是「改动检查」） | 9 · 7 · 10 | 已剥离进发布流程步骤：9 挂实发前，7 / 10 挂实发后（见 SKILL.md §八） |

**改动类型 → 追加的人工项**

| 类型 | 改了什么 | 追加项 |
|---|---|---|
| T1 | 元信息 / frontmatter | 4（仅在动了 README 或结构类字段时）；纯 description / summary 文案改动只需 `eval_trigger.py --desc-check` |
| T2 | SKILL.md 行为规则（触发词 / 流程 / 边界 / 示例） | 13 —— **不可豁免**：触发正确性无法靠自动检查补偿 |
| T3 | `scripts/` 脚本 | 8 · 13 · 14 · 15 |
| T4 | `references/` 参考文档 | 无（内容合规由自动项 1 / 16 兜底） |
| T5 | 目录结构 / 增删文件 | 4 · 8 · 12 |
| T6 | `evals/` 评测资产 | 12（确认评测产物是否该排除出发布包） |

**判定规则**

- 改动横跨多类型 → **取并集**（宁多勿漏）；无法确定改动边界 → **升级为全量**。
- 首次发布 / 大版本 / 失效触发随诊即改 → 全量，不启用分级。
- **启用边界**：分级制只服务「小改动快速迭代」。一个技能半年才发一次版，直接全量即可——为省几项人工而引入一套体系，本身就是负担。
- **不可逆步骤不受分级影响**：实发（`skillhub publish` / `git push` / 打 tag）在任何改动类型下都要 dry-run + 目录快照 + 人工确认。
- **与 preflight 分级正交**：preflight 的 critical / warning 管「命中后是阻断还是可豁免」；改动分级管「要不要跑这一项」。两层不冲突，勿混为一谈。
- **与版本号自然衔接**：T1 / T2 / T4 → PATCH；T3 / T6 → MINOR；T5 视影响（资源增删 MINOR，接口变动 MAJOR）。
- **先判类型靠 `git diff --stat`**，对照上表手判。暂不提供自动分类脚本：自动分类误判的代价高于手判的时间成本，待手判经验积累后再评估是否固化。


## 门禁分级（preflight_release.py 判定口径）

> 先分级，再决定是「改」还是「豁免」。critical 只能改；warning 可带理由豁免并留痕。

| 级别 | 项 | 默认行为 | `--strict` |
|---|---|---|---|
| **critical（阻断）** | 敏感信息命中（API key / 云凭据 / 明文 token / 明文密码赋值）、LICENSE 缺失或无 `Copyright (c)` 行、必含文件缺失或必含目录为空、frontmatter 必填字段缺失 / `version` 非 X.Y.Z | FAIL（exit 1） | FAIL（exit 1） |
| **warning（告警）** | author 缺失、frontmatter 建议字段、**name 不符合 kebab-case 或与目录名不一致**、**SKILL.md 正文体积超硬上限**、**§ 章节引用断链**、**version 低于已有 tag**、**声明了评测却无 `evals/`**、本地路径（`/Users/...`）、邮箱、疑似密码格式、git 未跟踪文件 | WARN（exit 0） | FAIL（exit 1） |
| **可豁免** | warning 级全部 | `--waive <项> --reason "<理由>"` → 落盘留痕并放行（exit 0） | 同样放行（exit 0） |

**豁免 key**（稳定标识符，与中文「说明」解耦——**不要把说明文案当匹配键**，文案一改就失效）：

| key | 命中内容 |
|---|---|
| `localpath` | 本机绝对路径（形如 `/Users/<user>`） |
| `homepath` | Linux 用户路径（形如 `/home/<user>`） |
| `email` | 邮箱地址（形如 `git@<host>` 的写法也会命中） |
| `password_format` | 疑似密码：5–9 位字母数字 + 连字符 ×3 的模式（**技能自身名与 CSS `prefers-*` 前缀已自动豁免**；第三方锁定/压缩文件默认整体跳过，其余形态误报才需本豁免） |
| `phone` | 手机号 |
| `author` | frontmatter 缺 author（**仅**这一项；LICENSE Copyright 行不受影响，仍是 critical） |
| `untracked` | git 未跟踪文件 |
| `ownership` | 归属检查整组（author + LICENSE Copyright 行） |
| `dangling_ref` | § 章节引用断链（目标文件里没有该章节） |
| `version_tag` | `version` 低于仓库已有 tag（疑似版本回退） |
| `eval_claim` | 声明了评测能力但 `evals/` 缺失或为空 |

```bash
# 豁免：--waive 可多次传入，--reason 必填（无理由豁免 = 无审计，直接报参数错误 exit 2）
python3 scripts/preflight_release.py . --platform skillhub --strict \
  --waive localpath --waive email --reason "文档示例路径，非真实个人信息"

# 向后兼容：--skip-ownership 保留为 --waive ownership 的别名，但不落盘
python3 scripts/preflight_release.py . --skip-ownership
```

- **critical 拒绝豁免**：`--waive openai_key` 之类直接报参数错误（exit 2）。真敏感只能删 + 轮换，豁免口子不给它留。
- **落盘审计**：豁免写入 `<目标目录>/.preflight-waiver.json`，记录 项 / 理由 / 时间 / 操作者 / 版本号。**发布前删掉它**——SkillHub 目录直发会把这个文件一起带上。
- **FAIL 必带修复指引**：每条 critical 后面跟一行「修：…」，`--quiet` 下也照样打印（CI 里只看见 FAIL 却不知道改哪儿，等于门禁在制造噪音）。
- ⚠️ 表内「frontmatter 建议字段」当前**脚本无独立检查项**：必填字段缺失按 critical 判 FAIL，非必填的建议字段缺失不产生任何告警。该行是规范口径，不代表脚本现状。

### 门禁可信任度：误报率必须 < 10%

> **门槛线的误报率（假阳性率）必须 < 10%，否则等于没有门禁**——一条总在报警的门禁，执行者最后只会学会忽略它。

**怎么统计**：每次 `--strict` 跑完，人工过一遍输出，数两个数——「命中总数」与「其中确实是问题的条数」；**误报率 = 误报数 ÷ 命中数**。命中数太少（不足一屏）时先攒样本，不要拿三五条就下结论。

**阈值与动作**：

- **误报率 > 10%** → **先修规则，再谈合规**。停下发布动作，回到规则本身：模式是不是缺数字边界、是不是拿本技能的语境当通用基准、是不是把合法写法当成了违规。
- **不要**用逐条 `--waive` 或往白名单里加条目把噪音压下去。豁免是给「确属误报的零星个例」用的出口，不是清理批量噪音的拖把——一旦用它代替修规则，规则本身永远学不会变准。

**为什么这条是硬线（本条的关键）**：误报率一高，执行者会学会两件事——**无脑豁免**，或者干脆**跳过门禁**。这比没有门禁更糟：它制造「已经检查过了」的错觉。没有门禁时人知道自己在裸奔；误报率高的门禁让人以为穿着盔甲。

**新规则上线前先拿存量样本跑一遍**：曾出现新加的门禁规则在存量样本上首跑时「命中若干项、逐条人工核对后**全部为误报**」的情形——这正是本条要求「新规则先跑存量、看清命中构成，再决定是留是改」的直接理由。新规则在存量样本上零真问题却批量命中，就该在装进发布链之前先收窄。

## 一键执行顺序

```bash
# 0) 依赖自检（脚本 import 的第三方包在 SKILL.md / requirements.txt 里声明了吗）
python3 scripts/check_deps.py <技能目录>

# 0.5) 清缓存 —— 跑过 py_compile / 脚本自测一定会有 __pycache__，
#      它会被目录直发带上、也会把 preflight 的文件计数算高（见踩坑表）
find <技能目录> -name __pycache__ -type d -exec rm -rf {} + 2>/dev/null; \
  find <技能目录> -name '*.pyc' -delete 2>/dev/null

# 1) 发布前预检（自动覆盖 1/3/5/6/16）
python3 scripts/preflight_release.py <技能目录> --platform skillhub

# 2) SkillHub 目录直发（默认路径，v2026.8.5+ CLI；先 dry-run 再实发）
#    ⚠ 直发前确认发布目录内无 LICENSE —— CLI 收集文件不排除它（清单 11）
skillhub publish <技能目录> --dry-run --json
skillhub publish <技能目录> --changelog "..."
#    （可选）离线归档或需要定制包时才用：python3 scripts/make_skillhub_zip.py <技能目录>

# 3) GitHub tag 保护（可选，仅 GitHub 发布）
python3 scripts/setup_gh_ruleset.py --dry-run && python3 scripts/setup_gh_ruleset.py

# 4) GitHub 发布
gh repo create <owner>/<name> --public --description "..." --homepage "https://github.com/<owner>/<name>"
# 推送（沙箱/透明代理环境必须绕过代理，详见下方「GitHub 推送踩坑」）
env -u HTTPS_PROXY -u https_proxy -u HTTP_PROXY -u http_proxy -u ALL_PROXY -u all_proxy \
  git -c http.version=HTTP/1.1 push -u origin main
git tag -s vX.Y.Z -m "..." && git push origin vX.Y.Z
python3 scripts/setup_gh_ruleset.py
```

## 失败降级路径（失败点 → 降级动作）

> 发布链条约 30 个原子步，任一步都可能失败。**先查这张表再想下一步**——多数失败有既定绕法，反复重试不是方案。

| 失败点 | 降级动作 |
|---|---|
| SkillHub 直发 400（含 LICENSE） | rsync 构造 staging 目录排除 LICENSE 后重发；同版本已占用则 bump 后再发 |
| 同版本已存在 | **bump 版本号后重发**，禁止删库重来 |
| 预检 critical 不通过 | 修复后重跑；属真敏感命中不得豁免 |
| 预检 warning 需放行 | `--waive <项> --reason <文本>`（可多次传入）落盘留痕后继续；key 与分级见上文「门禁分级」 |
| 安全扫描挂起 / download 404 | 以 publish 返回 `tags.latest` 为准，扫描队列异步等待（见下文「发布后验证」） |
| `git push` 报 HTTP2 framing / 空回复 | 清空代理变量并降级 HTTP/1.1（见下文「GitHub 推送踩坑」）；仍失败用 `gh api` Contents API 兜底 |
| GitHub tag 推送后发现版本错 | **不可删**——bump 到下一版本重发并公告；禁止临时关闭 ruleset |

## 归属与权益（三档判定）

| 档位 | 必做动作 |
|---|---|
| 已发布自研 | author + LICENSE `Copyright (c)` 行 + homepage 仓库 URL **三处一致**且仓库真实存在；提交用签名密钥 |
| 未发布自用 | frontmatter 预留 author/homepage 元数据即可，LICENSE 可后补 |
| 第三方安装 | **不碰**——不改 author、不标自己为版权人 |

发布前 5 分钟：预检（Copyright 为 critical 必拦；author 为 warning，需强约束用 `--strict`）→ homepage `gh api` 可达 → 三处一致 → 确不需归属时 `--skip-ownership` 并声明理由。

## GitHub 推送踩坑（透明代理环境）

环境存在 `HTTP(S)_PROXY=127.0.0.1:<port>` 透明代理时，`git push` 会报
`Error in the HTTP2 framing layer` 或 `Empty reply from server`。

**方案**：推送时清空代理变量并降级 HTTP/1.1（命令见上方 4）。
`gh` 子命令本身不受影响，可正常走代理；只有 `git` 的 HTTPS 传输会挂。

**签名配置**：无全局 `~/.gitconfig` 时按仓库设置（勿写全局）：

```bash
git config user.name <owner>
git config user.email <owner>@users.noreply.github.com
git config gpg.format ssh
git config user.signingkey ~/.ssh/<签名私钥>.pub   # 指向 .pub，私钥同目录无口令
git commit -S -m "..."                            # 必须显式 -S
```

**验签**（本环境 curl 直连 github.com 返回 HTTP 000，勿用 curl 判可达）：

```bash
gh api repos/<owner>/<repo>/commits/main --jq '.sha[0:7] + "  verified=" + (.commit.verification.verified|tostring) + "  " + (.commit.verification.reason // "-")'
# 期望: verified=true  valid
```

## 发布后验证：等扫描队列

SkillHub 发布成功 ≠ 立即可验证。平台返回 `securityScanStatus/reviewStatus: pending` 期间：

- `skillhub install <slug>@<ver>` → 下载端点 HTTP 404
- `skillhub search <slug>` → 索引无精确匹配（被模糊结果淹没）
- `skillhub verify <slug>@<ver>` →「找不到该版本」

**判据**：以 publish 返回的 `tags.latest` 与 `skillId` 为准，扫描通过后再补验。

```bash
# 查扫描状态（keen=朱雀 / sanbu=云鼎，两者都通过才放通下载）
TOKEN=$(skillhub auth token)
curl -s -H "Authorization: Bearer $TOKEN" "https://api.skillhub.cn/api/v1/skills/<slug>" \
  | python3 -c "import json,sys; d=json.load(sys.stdin); print({k:v['status'] for k,v in d['securityReports'].items()})"

# 通过后补验（先装到临时目录，勿污染技能目录）
skillhub --dir /tmp/sh_verify install <slug>@<ver>
skillhub --dir /tmp/sh_verify verify <slug>@<ver> --json   # ok=true 退出码 0
```

**板块归属**：`publish` 固定发到社区源（`source: community`，即 Skill 板块）；
插件板块属另一发行源（DSH 专用），CLI 无此选项，`skh_` 个人 token 不会误发。

## 踩坑表（14 条）

> 从 SKILL.md 正文下沉至此（控正文体积）。发布前扫一遍。

| 坑 | 根因 | 方案 |
|---|---|---|
| SkillHub 拒收 LICENSE | 平台不允许该文件类型（400） | 发布目录排除 LICENSE，frontmatter `license:` 字段声明 |
| 目录直发把 LICENSE 带上去 | skillhub CLI 收集文件仅排除 .git/__pycache__ 等，**不排除 LICENSE**；dry-run 只做 metadata 校验不检文件白名单 | 直发前人工确认目录无 LICENSE（或先 zip 路径用 make_skillhub_zip 排除），被 400 拒后删文件重发 |

| 发布后 verify / search / install 全挂 | 平台安全扫描排队中，未放通下载与索引 | 以 publish 返回的 `tags.latest` + `skillId` 为准；`securityReports.keen/sanbu` 通过后补验（命令见上文「发布后验证：等扫描队列」） |

| `password_format` 误报「疑似密码(x-x-x 格式)」 | CSS 属性名 / 三段式技能名 / 依赖包名 / 测试夹具名 / 仓库名命中 `x-x-x` 连字符模式（曾实测 6 技能 39 项 strict 失败里 36 项为误报，误报率 92%） | **已降噪（四层判据）**：技能自身名**及其片段**、已声明依赖包名、标准 HTTP 头 / CSS 厂商前缀、纯词形 kebab 串（每段全字母且含元音）一律不计；`package-lock.json`/`yarn.lock`/`poetry.lock`/`*.min.js`/`*.map` 默认跳过并计数留痕。手机号同理豁免测试假号、低数字多样性号码与路径段形式（GitHub 用户名）；`/Users/xxx` 类占位路径不计。**残余误报才用 `--waive`**——豁免是给零星个例的出口，不是清理批量噪音的拖把 |

| SkillHub 拒收 `.log` / `.enex`（2026-08-29 实测） | 平台文件类型白名单比文档认知更窄：评测产物 run.log、Evernote 夹具 .enex 均报 400「不允许的文件类型」，且 400 逐文件报、一次只报一个 | 发布前清 evals/case-\*/output/ 与 benchmark.json（可再生产物）；含 `.log`/`.enex` 等非常规扩展名的资产（evals fixture）走「SkillHub 不带、GitHub 全量带」策略——临时移出目录发布后还原；SkillHub 侧 11 文件 = SKILL.md + 全部 scripts + CHANGELOG + references |
| `git push` **各种姿势全败**，误判为「网络彻底不通」而放弃发布 | 上一行的代理降级只治 HTTPS 传输层；当透明代理把三种姿势（直连 / 清代理变量 / 降 HTTP/1.1）**全部**拦掉时，`git` 侧已无路可走 | **判据：`gh` 子命令仍可用 ⇒ 断的不是网络，只是 git 的传输通道**。此时换通道而不是反复重试——`scripts/gh_push_files.py` 走 GitHub Contents API 推送目录（命令与适用边界见 `脚本速查.md` §6）。三轮重试不成功即转兜底，别把「再试一次」当方案 |
| 用 Git Data API 在**空仓库**建 blob 报 `409 Conflict` | Git Data API 的建树/建 blob 假定仓库已有至少一个提交；新仓库尚未 init 时无父提交，blob 无处挂 | 先走 Contents API 提交一次完成初始化，再切 Git Data API；或**直接用 Contents API 全程推送**（本技能 `gh_push_files.py` 即此路线，天然不踩该坑）。读外部素材若见 Git Data API 方案，先确认它是否附带了空仓库初始化这一步 |
| `python3 -m py_compile scripts/*.py` 做语法检查后，preflight 报 **`scripts/ (6 个文件)`**（实际只有 3 个） | `py_compile` 会就地生成 `scripts/__pycache__/*.pyc`；preflight 的文件计数**不过滤缓存目录**，于是把编译产物算进了包体 | **顺序问题**：语法检查 / 脚本自测 → **先清 `find . -name __pycache__ -exec rm -rf {} +` 与 `*.pyc`** → 再跑 preflight 与目录直发。`make_skillhub_zip.py` 会排除 `__pycache__`，但**目录直发路径不排除**（同 LICENSE 那条坑的同一根因）；计数异常先看有没有缓存目录 |
