## 1. 可靠性数学（先算账，再动手）

**要点**：Agent 是复合不可靠系统——99% 单步成功率 × 8 步 ≈ 92%；25 步 + 工具调用真实场景 <70%（工具调用成功率约 97%，低于 LLM 本身约 99%）。生产部署 20% 是提示词工程、80% 是系统工程。**先按步数预估可靠性，步数越多，越要引入校验点、检查点与自动降级。**

```python
def expected_reliability(steps: int, per_step: float = 0.99) -> float:
    """预估整体成功率：reliability(steps) = per_step ** steps"""
    return per_step ** steps

print(round(expected_reliability(8), 3))    # 0.923
print(round(expected_reliability(25), 3))   # 0.778（乐观估计，未含工具调用约 97%）
print(round(0.97 ** 25, 3))                 # 0.467（纯工具调用 25 步的真实下限）

# 用法：步数 > 15 时，强制在流程中插入「校验点 + 自动重试 + 失败路径」
if expected_reliability(len(STEP_LIST)) < 0.90:
    print("流程过长，必须补：结构化输出、错误分级退避、幂等、降级链")
```

## 2. 强制结构化输出（消除约 80% 生产问题）

**要点**：用 schema 约束输出（Zod/Pydantic 等），**绝不解析自由文本**；解析失败即显式失败，不猜测；结构化校验可挽回约 85% 畸形输出。LLM 输出必须过 schema 再进业务逻辑。

```python
import json

# 不这样做：re.search 抓 JSON、字符串 split 取字段（畸形输出静默污染数据）
# 正确做法：schema 校验，失败即报错，拒绝进入下一步
SCHEMA = {"name": str, "code": str, "values": list}

def validate_output(raw: str) -> dict:
    try:
        data = json.loads(raw)
    except json.JSONDecodeError as e:
        raise ValueError(f"JSON 解析失败，请按 schema 重新输出: {e}") from e
    # 字段级校验：类型 + 非空（防假成功的关键）
    for k, t in SCHEMA.items():
        if k not in data or not isinstance(data[k], t) or data[k] == "":
            raise ValueError(f"字段 {k} 缺失或类型错误（期望 {t.__name__}）: {json.dumps(data, ensure_ascii=False)[:120]}")
    return data
```

## 3. 错误分级 + 指数退避（可重试 vs 永久分开）

**要点**：可重试（408/429/500/502/503/504/超时/JSON 解析失败）→ 指数退避 + jitter（1s→2s→4s→8s，封顶 60s）；永久错误（400/401/403/404/422/校验失败）→ 立即停止上报，不浪费重试。**禁止「一律重试 3 次」**。

```python
import random, time

RETRYABLE = {408, 429, 500, 502, 503, 504}

def retry_with_backoff(fn, max_retries=4, base=1.0, cap=60.0):
    """指数退避 + jitter：1s→2s→4s→8s 封顶 60s；永久错误不重试。"""
    for attempt in range(max_retries + 1):
        try:
            return fn()
        except HTTPError as e:                      # 伪代码，按实际异常替换
            if e.status in RETRYABLE and attempt < max_retries:
                sleep = min(cap, base * (2 ** attempt)) + random.uniform(0, 0.5)
                time.sleep(sleep)
                continue
            raise  # 永久错误或重试耗尽 → 显式失败，禁止静默吞掉
    raise RuntimeError("重试耗尽")

def http_call(url):
    resp = requests.get(url, timeout=10)
    if resp.status_code != 200:
        raise HTTPError(resp.status_code)
    return resp.json()
```

## 4. 工具失败协议（`is_error` + 像人话）

**要点**：工具返回统一带 `is_error` 标志；错误消息要像人话——**问题定位 + 正确格式示例**，而非笼统错误码。AI 才能据此自愈，人也才能据此修复。

```python
# 工具/函数返回协议（对 LLM 与下游同样适用）
def tool_result(content, is_error=False, retryable=False):
    return {
        "type": "tool_result",
        "is_error": is_error,
        "retryable": retryable,
        "content": content,
    }

# 错误消息模板：问题定位 + 正确示例（可读、可自愈）
def err_invalid_date(v):
    return tool_result(
        f"日期格式无效: {v!r}。请使用 ISO 8601 格式 YYYY-MM-DD（例如 2026-08-24），"
        f"而不是 {v!r}。",
        is_error=True, retryable=False,
    )
```

## 5. 写操作必须幂等（幂等键 + 缓存 TTL）

**要点**：幂等键 = 工具名 + 参数哈希；缓存结果带 TTL；超时重试不得重复写入。适用于「建单、发消息、写库、上传」等所有有副作用操作。

```python
import hashlib, time

_RESULT_CACHE: dict[str, tuple[float, object]] = {}

def idempotency_key(tool: str, params: dict) -> str:
    raw = tool + "|" + json.dumps(params, sort_keys=True, ensure_ascii=False)
    return hashlib.sha256(raw.encode()).hexdigest()

def idempotent_write(tool, params, ttl=3600):
    """同一工具+同参数在 TTL 内只执行一次；重试时直接返回首次结果。"""
    key = idempotency_key(tool, params)
    hit = _RESULT_CACHE.get(key)
    if hit and time.time() - hit[0] < ttl:
        return hit[1]
    result = do_write(tool, params)          # 真实写操作
    _RESULT_CACHE[key] = (time.time(), result)
    return result
```

## 6. 防失控护栏（硬上限 + 死循环检测）

**要点**：max steps / max cost / max duration 硬上限；语义相似度检测防重复循环；越界自动升级（停止→询问→降级）。**护栏必须硬性截断，不能只记日志。**

```python
class LoopGuard:
    def __init__(self, max_steps=20, max_cost=5.0, max_duration_s=300):
        self.steps, self.cost, self.start = 0, 0.0, time.time()
        self.limits = (max_steps, max_cost, max_duration_s)

    def check(self, step_cost: float) -> None:
        self.steps += 1
        self.cost += step_cost
        if self.steps > self.limits[0]:
            raise RuntimeError(f"超步骤上限 {self.limits[0]}，中止")
        if self.cost > self.limits[1]:
            raise RuntimeError(f"超成本上限 ¥{self.limits[1]}，中止")
        if time.time() - self.start > self.limits[2]:
            raise RuntimeError(f"超时长上限 {self.limits[2]}s，中止")

def similar(a: str, b: str) -> float:
    """语义相似度检测（轻量：Jaccard 字符 n-gram；重判断可换 embedding）。"""
    def grams(s, n=3):
        return {s[i:i+n] for i in range(max(0, len(s) - n + 1))}
    ga, gb = grams(a), grams(b)
    return len(ga & gb) / max(1, len(ga | gb))

# 编排循环中：每轮 guard.check(...)；若本轮输出与上轮相似 > 0.9 → 判定死循环中止
```

## 7. 统一返回信封（不裸返回）

**要点**：成功 `{ok:true, data:{...}}`；失败 `{ok:false, error:{code, message, retryable}}`；分页用 `next_cursor`；**绝不返回裸字符串或整表 dump**（整表 dump 是 token 与上下文污染大户）。

```python
def ok(data=None):   return {"ok": True,  "data": data}
def fail(code, message, retryable=False):
    return {"ok": False, "error": {"code": code, "message": message, "retryable": retryable}}

def page(data, limit, cursor=None, next_cursor=None):
    return ok({"items": data, "limit": limit, "cursor": cursor, "next_cursor": next_cursor})

# 消费方统一判定，拒绝裸字符串：
r = some_tool_call()
if not r.get("ok"):
    e = r["error"]
    raise RuntimeError(f"[{e['code']}] {e['message']} retryable={e['retryable']}")
```

## 8. 让非法状态不可表示（enum / 闭集）

**要点**：能枚举的状态用 enum；不要传两个互相矛盾的布尔参数；schema 开 `additionalProperties:false`。**设计上让非法状态无法被表达，而不是靠运行时校验兜底。**

```python
from enum import Enum

class LightState(Enum):
    ON = "on"
    OFF = "off"

# 反模式：set_light(on=True, off=True) 组合出非法状态 → 改成单一参数
def set_light(state: LightState) -> dict:
    if not isinstance(state, LightState):
        raise ValueError(f"state 必须是 LightState（on/off），收到 {state!r}")
    return ok({"state": state.value})

# schema 层面：additionalProperties: false 拒绝多余字段
SCHEMA_STRICT = {"type": "object", "properties": {"state": {"enum": ["on", "off"]}},
                 "required": ["state"], "additionalProperties": False}
```

## 9. 破坏性操作人工审批（HITL）

**要点**：发布、交易、删除、覆盖写等破坏性操作前**插入审批点**，并提供 diff/预览供人确认；审批前不执行。适用场景：发布技能、批量删除、改写用户文件、对外发消息。

```python
def confirm_destructive(action_desc: str, diff: str) -> bool:
    """打印 diff/预览，要求人工确认。返回 True 才允许继续。"""
    print(f"即将执行破坏性操作: {action_desc}")
    print(f"预览:\n{diff}")
    ans = input("确认执行? [y/N] ").strip().lower()
    return ans in ("y", "yes")

if not confirm_destructive(
        f"发布 skill 到 SkillHub（version={version}）",
        "\n".join(f"  + {f}" for f in new_files)):
    sys.exit("已取消（HITL 审批未通过）")
```

## 10. 降级链 + 防假成功（个人实战贡献）

**要点**：多源自动降级（例：企查查 → 启信宝 → 公开源）；**必须校验关键字段非空**——最大 bug 是接口返回空字段仍被当作成功。降级与假成功是两件事：降级换来源，校验挡空值，缺一不可。

```python
SOURCES = ["qcc", "qxb", "public"]          # 降级链（按可信度排序）

def fetch_company(name: str) -> dict:
    last_err = None
    for src in SOURCES:
        try:
            data = call_source(src, name)    # 伪代码
        except Exception as e:
            last_err = e; continue
        # 防假成功：关键字段非空才接受；空字段 = 失败，继续降级
        if not data.get("name") or not data.get("credit_code"):
            last_err = ValueError(f"{src} 返回空关键字段: {data!r}")
            continue
        return data
    raise RuntimeError(f"所有数据源均失败，最后错误: {last_err}")

# 反模式（血泪案例）：resp.json() 返回 {"credit_code": null} 仍被当作成功写入下游
```

## 验收三连（写完后自检）

1. **错误路径**：构造错误输入（空字段 / 畸形 JSON / 500 响应 / 重复调用）逐一跑通，拦截率 100%。
2. **失败可见**：所有失败要么显式抛错、要么返回 `{ok:false, error}`——无一处静默吞掉。
3. **幂等复跑**：同一任务连跑两次，结果一致、副作用不重复。
