# Changelog（版本史）

> 版本号语义化 X.Y.Z：Z 修复与体验优化 / Y 功能新增 / X 结构性升级。

## 1.18.0 版本发布（2026-10-01）

- **调整**：对外写作检查的范围扩为**随包对外 markdown**——`references/` 全部子目录与版本档案一并纳入，不再按目录整片豁免；并按读者远近分两档：第一读者面（对外入口 + 版本档案）恒判，`references/` 深层面按 `--scope` 分档
- **调整**：`references/` 类改动不再视为无需人工检查，改为触发三视角语义通读
- **新增**：按文件声明豁免（`dev_process@references/<文件名>`），路径不存在直接报错；豁免理由与**实际放行处数**一并落盘，零命中会标成「休眠」
- **新增**：豁免可落盘复用（`--waive-file`），让批量体检 / CI 与发布命令得到同一结论
- **新增**：预检报告打印对外写作检查的 `目标 / 实查` 份数与读不出的文件清单——**范围与「没查到的」都可见**
- **调整**：三视角语义通读改由**独立子代理**执行，回报三视角结论 + 逐条问题 + 已读文件数，不再要求产出独立清单；该步骤不受改动分级裁剪
- **修复**：版本档案原先被当普通参考文档处理，可被自用档放宽，与检查注释的承诺相反；现归入第一读者面
- **修复**：文档中间的 `---` 水平线会翻转 frontmatter 状态，使其后整篇不再被扫；现只认文件开头的 `---`
- **修复**：`references/` 下一个非 UTF-8 的 `.md` 会让预检以 traceback 中断；现捕获并计入「未读到」
- **修复**：引用检查、加载元数据检查与版本档案发现只看一层目录，与对外写作检查的递归口径不一致；现统一
- **优化**：`--quiet` 的结果行补上正文体积读数，避免读数看不见被当成达标
- **新增**：豁免情况写进结果行（`--quiet` 下也在）：`豁免 N 项（休眠 M）`；用了全局 `dev_process` 再带出「连带放行第一读者面 X 处」
- **新增**：三视角语义通读补「**整改后复核轮**」——改完由同一视角复读一遍，核对改动是否真的落地
- **修复**：`setup_gh_ruleset.py` 原先默认不写 `conditions`，而空的 `conditions` 不匹配任何 tag ⇒ 规则形同虚设；现强制写入 `refs/tags/*`，建完回读自证，`--list` 会标注空 refs
- **调整**：本技能的发布流程只覆盖 **SkillHub + GitHub** 两个渠道；原先附在发布清单里的「第三渠道（WorkBuddy 开放平台）」说明已拆出为**独立资产**（含平台对照、打包规格、草稿锁、类目下拉、专业领域专条与取数接口）
- **优化**：发布检查清单补三条踩坑（frontmatter 冒号陷阱与 `--strict` 的关系、`gh` 凭据别用环境变量覆盖 keyring、tag 保护探针别拿真 tag 试）与签名配置说明
- **优化**：评测聚合不再默认写进技能目录，改写到临时目录（更新包内记录须显式指定输出路径）

## 1.17.0 版本发布（2026-09-30）

- **新增**：版本说明的写作模板——含收录判据、条目公式、量化边界、过滤方法与发布前自检清单，并附正反例对照
- **修复**：对外写作检查此前用「文件名含 changelog」识别版本档案，会把《Changelog写作模板》这类**方法论**文档误判为版本档案；现按其主题词排除模板 / 规范 / 指南 / 写作类文件

## 1.16.0 版本发布（2026-09-30）
- **修复**：发布预检的「对外写作」检查此前只覆盖 SKILL.md 与 README，版本说明没被纳入——结果是把开发过程信息留在版本说明里也能通过检查。现已把版本说明一并纳入检查面，并对版本说明加查「写作规则自曝」这一类元说明；本技能自身已通过同一检查

- **新增**：发布流程新增「三视角语义通读」步骤——发布前以陌生用户 / 竞品 / 法务三视角通读 SKILL.md + README + references，产出点名对象 / 外部不可达引用 / 内部坐标三份清单，作为发布必需产物
- **新增**：发布预检新增三项——文档引用指向不可达的内部资料、参考文档点名第三方并打分或贬损、文档声明的门槛与脚本实现不一致，三者都会提示；门槛不一致按方向分级处理
- **新增**：触发词评估纳入发布流程步骤 0 必做项——改过触发词或 name/displayName 的版本必须跑触发词评估并随报告归档
- **新增**：转手发布（发布者 ≠ 作者）纪律——合并上游产包时，diff 通过 ≠ 语义合规，上游内容一律按「新内容」走三视角语义通读
- **修复**：依赖自检在旧版 Python（3.9）下把标准库误判为第三方依赖，已补全标准库表，跨解释器结果一致
- **修复**：评测循环此前「回归重跑」会静默跳过全部用例却仍报通过；现已能真正重跑，并默认拒绝执行用例自带命令（需显式确认），推送兜底脚本也改为默认只预览、确认后才落远端
- **优化**：发布预检严格档的失败措辞由「高危问题」改为「阻断」，与真正的敏感信息高危区分开

- **新增**：固化方法论补「从**已有项目代码**固化」一节——泛化四步（剥壳 / 数据驱动化 / 下沉 / 实名代号化，每步都给了可 grep 的判据）+ **离线自证**：打包时附带一个本地演示环境，让"链路真的通"能在不碰真实账号的前提下验收。同时点明"只跑离线单测不足以证明链路通"这一常见自欺
- **修复**：打包工具原先只排除 LICENSE，README 会随包上传——与「包内不含 LICENSE 与 README.md」的约定冲突。现在两者都默认排除，且匹配不再区分大小写（`readme.MD` / `license` 这类也能拦住）；确需保留时用 `--keep-readme` / `--keep-license` 显式声明
- **新增**：发布预检增加一项——对外文档里出现开发过程信息时会提示，并给出改写方向
- **修复**：触发词评估工具同时传「覆盖率检查」与「description 质量检查」时，后者会**静默吞掉**前者——只报质量、不报覆盖率，使用者以为两侧都验过。现在两侧都跑，退出码取较严一侧
- **调整**：多模型逐一实测改为可选条件项，不再是发布要求，也不再需要豁免
- **优化**：发布清单与脚本速查同步上述改动（LICENSE / README 排除、条件项说明、组合模式行为）
- **新增**：改动已有技能时，若属批量重构，验收环节增加「证明内容没丢」的校验方法，并配套两条纪律：动手前先定义可逆性来源、结构重排与内容修改分两次做

## 1.13.1 版本发布（2026-09-13）

- **修复**：自身评测的证据切片取错了行——「发布检查清单」顶部是元数据块，取首行只会拿到分隔线而拿不到标题，导致评测分数在同一份包内对不上（包内记录与实际重跑不一致）。现在按首个标题行取
- **优化**：发布预检的「打包卫生」检查不再报告缓存文件——缓存本来就被打包脚本排除、进不了包，报出来只会让报告多出需要人工解释的行；该检查现在只盯「会被真打进包」的临时与备份文件
- **优化**：发布预检调用同目录脚本时，不再在被检技能的目录里留下缓存文件——预检是只读的，不该在检查对象上留下痕迹

## 1.13.0 版本发布（2026-09-13）

- **新增**：发布预检增加第 9 节「结构规范检查」——一次预检即可同时核对：正文里引用的文件是否真实存在、description 的触发面是否完整（排他边界与口语触发词示例）、frontmatter 有无品牌保留词、以及冒号与多行写法带来的截断风险
- **新增**：预检再增两项——**打包卫生**（`.bak` / `.tmp` / `~$*` / `.swp` 这类临时文件不在打包排除名单里、会真被发出去，现在发布前就拦下）与**路由表 doNotUse 列**提示；参考文档的「加载条件」开始按强路由句式给建议
- **新增**：SKILL.md 增加「输出文件约定」一节——一次说清产物写到哪、怎么命名、什么格式、失败时留下什么
- **新增**：正文补上边界输入清单、本机与其他技能的生态分工、以及发布链中断后的续跑锚点
- **优化**：该节另登记若干整洁信息（包内含 README、未被正文引用的文件、参考文档缺少加载条件、索引记录的体量与实际行数不符、路由表缺 doNotUse 列）——只提示，不参与通过与否
- **优化**：预检结果分「告警」与「登记」两档，前者在 `--strict` 下阻断发布，后者永不阻断——不再为一个格式建议卡住整条发布
- **优化**：自身评测的证据从「章节转储」改为**真跑产物**，每份证据头部写明取得方式与可独立重跑的命令；评测同时输出**无技能基线对照**，让「技能到底有没有教出新东西」第一次可量化检验
- **优化**：随包 README 从技能目录移出（技能文件夹内不放 README.md，说明收敛到 SKILL.md 与 references/），仓库根 README 保留并同步更新
- **新增**：描述检查增加「触发词示例」一项
- **优化**：疑似密码、手机号、本机路径三条规则的误报大幅下降——技能自身名、依赖包名、标准 HTTP 头与 CSS 属性名、测试用假号码、GitHub 用户名等不再被误报；同一命中出现在多个文件时折叠为一行汇总，报告更短更好读
- **优化**：description 的场景词与动词词表扩充，紧贴中文的缩写（如「API 余额」「CSS 变量」）不再被判「未识别到场景」
- **修复**：前几版的多行写法 description 只会被读到第一行，导致触发面后段整体失效却看不出来；现在按 YAML 规则整段读取，并在预检里把这种写法单独提示出来
- **修复**：评测聚合读取中文产物时，文本探测窗口会截断多字节字符，导致体量较大的中文证据被静默漏评、分数偏低且看上去像「没通过」

## 1.11.0 版本发布（2026-09-12）

- 新增批量体检：一次给一批技能跑完同一套检查并汇总成一张结构对照表，不必再逐个手工调用；体检报告只留在本地工作区，不会写进被检查的技能目录
- 反模式清单每条补上「可观测判据」——出现什么现象就算踩了这条，可以逐条机械核对；同时新增一条：技能的实际行为与描述不符（含夹带恶意或利用性代码）即属缺陷
- 评测用例补上六条质量标准（独立、只读、复杂、真实、可验证、稳定），不满足就先改用例再谈分数；并新增回哺环节——多个用例各写一遍同一段脚本时，该把它收进公共脚本供调用，而不是让每个用例重复实现
- 写作指导补充：决策路径图的适用边界、什么时候不该拆分文件、面向协作者该选哪些词、命名与示例的质量取向
- 技能描述补充两条写法：写「触发前那一刻的症状」，以及描述问题本身、而不是某种语言特有的症状
- 每个脚本的帮助信息都给出可直接复制运行的示例，不必再翻文档猜参数
- 发布检查清单补「门禁可信任度」纪律：误报率超过一成时先修规则，再谈合规——否则执行者会学着无脑放行
- 技能迭代四步法标注为默认不执行：它依赖执行记录采集机制，机制未就绪时强行执行只会给出假信号
- 修正参考文档里一处过时的体积基准，以及两处指错目标的交叉引用
