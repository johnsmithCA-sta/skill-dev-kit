# 调试三步法（技能上线后的活诊断）

> 来源：个人技能运维实战。与 SKILL.md §十「踩坑表（历史坑）」互补——踩坑表是「已经踩过的坑」，本文件是「当下发生了什么」的活诊断。
> 适用：技能已发布但「没触发 / 乱做 / 输出不对」时，30 秒内定位到本文件照做。

---

## 总览：三类典型故障

| 症状 | 对应步 | 一句话判因 |
|---|---|---|
| 技能根本没被加载 | 第一步 | description 触发面太窄或格式错误 |
| 技能被加载但做错、脚本报错 | 第二步 | 正文指令特异性不足 / 脚本依赖路径权限问题 |
| 技能跑通但产物不对、格式乱 | 第三步 | 中间步骤歧义，缺调试钩子 |

---

## 第一步：未触发 → 拓宽 description

**症状**：用户说的是你预期内的场景，但技能静默、模型自己硬扛。

检查清单：

1. **场景覆盖**：description 是否含「功能 + 场景双维度」（动作动词 + 文件类型 + 场景）？只有「文档处理」这种泛词必死。
2. **排他边界**：是否写了「不做什么」？缺边界会导致模型认为「这不该我触发」。
3. **YAML 格式**：frontmatter 的 `description` 是否被引号误断行、是否含未转义特殊字符导致解析失败。
4. **任务复杂度**：简单单步任务本就不触发——这是**设计预期**，不是 bug。复杂多步才必触发（测试方法：用带错字/缩写/乱文件名的「真人说话」式复杂多步 prompt 测，简单 prompt 触发率天然低 90%）。

对策动作：
- 按 `references/SKILL.md 编写规范.md` §七 四策略重写 description。
- 用 `eval_trigger.py --desc-check` 静态校验；用 `eval_trigger.py --check` 确认「## 触发词」章节覆盖率达标。
- 把「某 prompt 没触发」当**新测试用例**补进 evals（评估驱动的反哺）。

---

## 第二步：执行不一致 / 脚本报错 → 增强指令特异性

**症状**：技能触发了，但步骤跳步、用错工具、脚本退出非 0、路径/权限报错。

检查清单：

1. **指令特异性**：是否用了 MUST / NEVER / ALWAYS 编码强制与建议？含糊的「可以」「建议」模型会自由发挥。
2. **脚本依赖/路径/权限**：脚本是否自包含？是否把 `/Users/xxx` 硬编码路径改成环境变量？运行账号是否对目标目录有读/写权限？
3. **指令歧义**：同一动作是否出现多种表述？示例是否只有一个（应补 2–3 个少样本）？
4. **工具选择**：是否出现「选错工具」vs「选对工具但参数错」两个独立失败面——分开定位、分开修。

对策动作：
- 歧义步骤改为**模板模式 / 少样本示例**：「好的示例胜过十条规则」。
- 脚本参数化：硬编码路径/账号 → 环境变量或命令行参数；硬编码文件名列表 → 目录自动扫描。
- 用 `eval_loop.py` 跑 case，看 grading.json 定位是「漏用规则」还是「参数错」。

---

## 第三步：输出异常 → 加临时调试模式

**症状**：流程跑完，但产物字段缺失、格式不对、顺序错乱。

检查清单：

1. **正文步骤歧义**：是否某步「读 A → 处理 → 写 B」的顺序没写清？
2. **结构化输出缺口**：复杂产物是否要求模型自由文本拼装（应改为 schema 约束，消除约 80% 生产问题）？
3. **验证缺口**：是否缺少「数量统计 + 逐条抽查 + 失败清单」三件套验收？

对策动作：
- **临时调试模式**：在正文插一段「先输出 [路径/格式/步骤清单] 再执行」的调试指令，定位断点；确认后移除。
- 关键产物加**结构化校验**（Pydantic/Zod / 正则校验器），解析失败即显式失败，不静默继续。
- 补「错误路径」用例——错误输入必须被拦截（参考 SKILL.md §五 四层测试闭环）。

---

## 速查卡（贴墙版）

```
没触发  → description 太窄/格式错 → 重写(四策略) + --desc-check
做错/报错 → 指令含糊/脚本依赖 → MUST编码 + 参数化 + 少样本
输出错  → 步骤歧义/无校验 → 临时调试模式 + 结构化输出 + 错误路径拦截
```
