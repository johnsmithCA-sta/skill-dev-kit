# 市场调研模板（轻量化 · 发布前必做）v1.3

> 本模板固化为 `skill-dev-kit` 标准资产。任何技能发布前套用本模板即可，无需重新设计调研方案。
> 核心约束：**常规只调研市场规模最大的前 5 家（3 头部 + 2 近 90 天新上架，双轨），不做全量普查；触发式经人工确认可放宽至 8 家（§3）。**
> 阅读约定：下文「Top5」指常规 5 家样本；走触发式扩至 8 家时，「Top5」读作「TopN（实际样本数）」。
> 产出深度基准：调研表 → 生态格局结论 → 独创性分析 → 商业竞争力速评 → 结论先行（五段递进，缺一不可）。

## 0. 产出总览（调研后必须交付 5 份固定件）

| # | 固定件 | 对应范本章节 |
|---|---|---|
| 1 | 调研对比表（Top5，每家一行） | 第二章 |

| 3 | 独创性分析（2–3 个维度 × 对比表 + 独特点结论） | 第三章 |

## 1. 目的

发布前快速定位市场空白与差异化机会，**不做全量普查**。只回答两个问题：

1. 我的技能相对头部竞品，差异点在哪里（能否一句话讲清定位）？
2. 是否存在明显重复 / 红海，需要规避或重新定位？

## 2. 调研对象选取规则（固定 · 不可突破）

- **唯一规则**：在目标领域（同类技能 / 竞品）内，按 **市场规模** 排序，取 **最大的前 5 家**。
- **规模排序依据**（按可获得性依次降级，取最先可用的口径）：
  1. 平台官方下载 / 安装 / 使用次数
  2. 评分 × 评论数（加权热度）
  3. 平台官方精选 / 编辑推荐 / 榜单排名
  4. 最近更新频率与活跃度
  5. 被其他技能引用 / 依赖次数
  6. **marketplace 收录数 / 跨 harness 复用数**——同一技能被几个不同 harness / marketplace 收录、能否跨 harness 直接复用（衡量平台内热度之外的**外部可移植性**）；取数：在候选平台逐个检索同名 / 同功能技能，统计被收录的 marketplace 数，并实测在 ≥2 个不同 harness 下能否加载运行。
  7. **MCP 依赖与被调用量**——依赖了哪些 MCP server、被哪些技能 / 客户端调用（衡量**生态嵌入深度**）；取数：读技能包 frontmatter 与配置清单提取 MCP 依赖列表，结合生态登记表的被调用 / 被引用计数。
- **规模档位校准**（社区实测，2026-08，仅作量级参照，不替代逐家取数）：全生态 skills 约 58.7k 档 / marketplaces 约 12.6k 档 / MCP servers 约 8.4k 档；单一大型索引 plugins 约 3.7k 档 / marketplaces 约 1.5k 档 / MCP 约 13.9k 档；单一安装入口累计安装约 877k 档；通用聚合入口约 3M 档。
- **数据缺失兜底**：若平台不提供规模数据，退化为「全站分类 Top5 + 官方精选」，并在对比表注明「规模数据缺失，按头部近似」。
- **硬上限**：常规调研只调研 **5 家**（3 家头部 + 2 家近 90 天新上架，见 §3）。全量普查（如原 240 样本做法）一律作废；仅**触发式调研**经人工确认并记录理由后可放宽至 8 家。
- **名单指定权**：Top5 具体名单可由用户 / 数据指定；若未指定，按上述规则自动确定。

## 3. 调研对比表（每家一行）

## 4. 生态格局结论（固定三段式，仿范本第二章）

调研表填完后，必须输出 3 条编号洞察：

1. **主流定位**：Top5 共性——"主流生态的 X 技能几乎全部是「A 定位」"；
2. **稀缺 / 空白**：Top5 中无人做的定位类型——"「B 定位」类极度稀缺：Top5 中仅 <N> 家"；
3. **最重要发现**：机会点一句话——"『<C>』在调研生态中未发现直接竞品——这是本次调研最重要的发现"。

> 模板句：主流生态的 <领域> 技能几乎全部是「<定位A>」；「<定位B>」类极度稀缺：Top5 中仅 <N> 家；"<C>"在所有生态中未发现直接竞品——这是本次调研最重要的发现。
> 若 Top5 无空白点（红海信号），第 3 条改为"本品需重新定位，理由：<证据>"。

> ⚠️ **幸存者偏差警示**（3 条写完必须自查，否则结论不成立）：
> 1. **只调研头部会系统性高估市场成熟度、低估空白**。头部是"已存活且被看见"的少数样本，其共性只能证明某条路径已被验证，不能证明空白不存在；因此第 2、3 条必须与 §3 新上架轨（#4–#5）交叉复核——只有新上架样本与头部定位趋同，才可判定为真红海。
> 2. **用通用入口（find-skills 一类的聚合入口，约 3M 量级）的规模数据去推断垂直领域空白是不成立的**。聚合入口的量级是全生态总和，与任一垂直细分的可供给量没有单调关系；垂直空白只能用该垂直领域内逐家取到的口径举证（优先 §2 ⑥⑦：marketplace 收录数 / 跨 harness 复用数、MCP 依赖与被调用量）。

## 8. 发布曝光配套（GitHub topics 与 awesome 收录）

> 前面七节解决「做给谁、跟谁比」；本节解决「做完了别人怎么找到」。仅 GitHub 侧发布有效——SkillHub 侧靠平台检索，跳过本节。

### 8.1 topics 选词：四象限取词 + 20 个硬上限

按四个象限各取 1–3 个，求**覆盖**而不是堆同义词：

| 象限 | 取什么 | 形态示意 |
|---|---|---|
| 平台 / 格式 | 产物形态或宿主平台的通用词 | `agent-skill`、`llm-tools` |
| 功能域 | 这个技能解决什么领域问题 | `code-review`、`data-viz` |
| 场景 / 角色 | 谁在什么场合用 | `developer-tools`、`content-ops` |
| 技术栈 | 实现或依赖的栈（**仅当真的相关**） | `python`、`github-actions` |

- **硬上限 20 个**（平台限制），**实用区间 6–10 个**——铺满 20 个不相干的词等于没有主题。
- **不选**：与技能无关的热门词（蹭流量会被识破）、纯品牌名、与 description 矛盾的词。
- topics 是**唯一不依赖 star 的曝光入口**：写进仓库后即被平台搜索与第三方目录抓取。

```bash
# 先看现有 topics，避免覆盖别处设置
gh api repos/<owner>/<repo>/topics
# 一次性 PUT（替换式：必须给全量；传空数组会清空）
gh api -X PUT repos/<owner>/<repo>/topics \
  -f names[]=agent-skill -f names[]=<功能域词> -f names[]=<场景词>
```

### 8.2 收进 awesome 列表：别在发布当天提 PR

| 门槛 | 判据 | 为什么 |
|---|---|---|
| **当天不提** | 发布 24 小时内不提交收录 PR | 列表维护者按「有没有人真的在用」筛。0 下载 0 star 的新仓库当天必被拒，而**被拒记录留在 PR 里**，重提时对方看得到 |
| **够量再提** | SkillHub 下载 ≥50，或 GitHub star ≥10 | 「已有真实使用」的最低可验证信号，比自述「很实用」有说服力得多 |
| **先看收录形态** | 目标列表是**链接型**（一行链接 + 简介）还是**注册表型**（要求可访问的 manifest / 安装命令） | 投错类型 = 白发一次 PR，且消耗一次被拒记录 |

> ⚠️ 被拒本身不是失败，**反复被拒**才是。第一次提之前把上表三栏逐一核对。

## 9. 硬约束与预算

- 只调研 **Top5**；每家 ≤ 1 次调研；扩展须经人工确认并记录理由。
- 数据缺失必须注明兜底口径（见 §2），不得隐瞒。
- 全程本地调研（公开页面 / 注册表 / 文档），不外泄任何敏感信息。

## 10. 用法

1. 复制本模板到技能 `references/` 或工作区。
2. 按「规模排序依据」确定 Top5 名单（§2）。
3. 逐家填对比表（§3，每家 ≤ 1 次）。
4. 依次产出 5 份固定件（§4–§7）：生态格局结论 → 独创性分析 → 竞争力速评 → 结论。
5. 调研结论作为 SKILL.md / 发布说明的「市场定位」依据，纳入发布前 16 项清单的参考输入（定位不清则重新调研）。
6. 自查深度：对照 §4–§7 五份固定件是否齐全、结论是否先行、生态格局是否有对比表数据支撑。
7. GitHub 侧发布后：按 §8.1 选 topics 并 PUT；够量后按 §8.2 提收录（**当天不提 PR**）。
